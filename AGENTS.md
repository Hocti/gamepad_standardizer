# gamepad_standardizer

A browser JavaScript/TypeScript library that normalizes gamepad input across different browsers and devices.

## Why this exists

The HTML5 Gamepad API behaves differently in Chrome vs Firefox, and many gamepads report as "non-standard" mapping. For example:
- Firefox does not mark PS5 controllers as standard — button indices shift, D-pad becomes a single axis value.
- Some gamepads expose a D-pad as two analog axes instead of four buttons.

This library fixes all of that by using the [SDL_GameControllerDB](https://github.com/gabomdq/SDL_GameControllerDB) database to remap inputs into a consistent format.

## Main API

All functions are exported from the package root.

### Setup (call once)

```ts
// Choose the SDL DB source. Default is { mode: 'fetch' } (GitHub raw + localStorage cache).
//   { mode: 'bundled' }                     → use per-platform JSON shipped in src/db/ (no network)
//   { mode: 'fetch', url?, cacheKey? }       → download SDL text, cache in localStorage
//   { mode: 'custom', text }                 → parse caller-supplied SDL text
configureDB(config: DBConfig)

// @deprecated — forwards to configureDB({ mode: 'fetch', url }). Kept for back-compat.
SDLDB_setLink(link: string)

// Load extra mappings for gamepads not in SDL DB
// Format: platform:X,browser:X,name:X,vendor:X,product:X,font:switch,...,a:b0,...
SDLDB_procesExtraText(text: string)

// Per-device overrides, for pads the *browser* maps wrongly (written in the browser's index
// space, not SDL's). External .txt files fetched at runtime; the shipped one is only a default.
configureLocalOverrides({ urls?: string[]; includeDefault?: boolean })
addLocalOverrideUrl(url: string)     // append a .txt path — loaded last, so it wins
addLocalOverrides(text: string)      // append inline text (file:// builds, settings screens)

// Pick the glyph artwork for a specific controller (xbox | playstation | switch)
addPadFontProfile(profile: PadFontProfile)
```

**Lazy DB contract:** the SDL DB *and* the override `.txt` files are loaded only when a
*non-standard* controller connects (inside `getGamepadInfo`). Standard / xinput controllers never
trigger a load — no bundled import, no fetch. Keep it that way when editing `getGamepadInfo` /
`ensureDB` / `ensureLocalOverrides`; `test/localOverride.test.ts` asserts it by spying on `fetch`.
Within the non-standard path the order is **overrides → extraGamepadDB → SDL DB**.

**Override file resolution:** `localOverride.ts` resolves the default `.txt` against its own module
URL (`import.meta.url`, falling back to `document.currentScript.src` in the iife build), so it lands
on `src/db/` under the "development" condition and `dist/db/` when built. `vite.config.ts` copies the
file verbatim — do **not** turn it into a literal `new URL('./…', import.meta.url)` asset import, as
Vite would content-hash the name and users could no longer find and hand-edit it.
A `file://` app (Electron) cannot fetch at all and must inline the text instead — see
`games/multiplay-template/src/input.ts`, which imports `gamepad_standardizer/local_override.txt?raw`.

**SDL parsing** lives in pure functions in `src/sdlParse.ts` (`parseSDLLine` / `parseSDLText` /
`parseSDLDict`) — reused by both the runtime and the `build:db` script. **DB source selection**
lives in `src/dbSource.ts` (`configureDB` / `ensureDB` / `currentPlatform`).

### Per-gamepad (call on gamepadconnected, then each frame)

```ts
// Step 1: get gamepad info (async — fetches SDL DB on first call if needed)
const info = await getGamepadInfo(gamepad: Gamepad): Promise<gamepadInfo>

// Step 2 (each frame): read inputs using the info object
getDirection(gamepad, info, threshold?)     // D-pad + analog sticks
getDirectionAvailable(info)                 // which direction sources exist
getExtraAnalog(gamepad, info)               // triggers and other non-stick axes
getButtonPress(gamepad, info, skipDpad?)    // button pressed state (boolean | null)[]
getButtonValue(gamepad, info, skipDpad?)    // button analog value (number | null)[]
getButtonName(info)                         // button labels (SDL standard names)
getButtonGlyphs(info, opts?)                // per-button glyph char + font-family
padFontId(info, opts?) / padFontFamily(...) // which gamepad_fonts family to draw with
installPadFonts(root?)                      // inject the @font-face rules once
```

### Return types

**`gamepadInfo`** — describes the controller:
- `standard: boolean` — whether browser already reports it as standard
- `buttonNames` — raw SDL button names at each index
- `analogNames` / `analogPlusNames` / `analogMinusNames` — axis labels
- `keyMapping` — remaps non-standard button indices to W3C standard indices
- `hatDpad` — how to read D-pad from a single hat axis value
- `originInfo` — raw browser gamepad metadata

**`directionWrap`** — result of `getDirection()` per source (`dpad`, `leftAnalog`, `rightAnalog`):
- `up / down / left / right: boolean`
- `x / y: number` (normalized, dead-zone applied)
- `numpad: number` (1–9, numpad layout)
- `degree: number` (0–359)
- `radian: number`
- `distance: number` (0–1)
- `type: 'analog' | 'dpad'`

## Typical usage pattern

```ts
import { getGamepadInfo, getDirection, getButtonPress, getButtonName } from 'gamepad_standardizer'

const infos = {}

window.addEventListener('gamepadconnected', async (e) => {
  infos[e.gamepad.index] = await getGamepadInfo(e.gamepad)
})

function loop() {
  for (const gp of navigator.getGamepads()) {
    if (!gp || !infos[gp.index]) continue
    const info = infos[gp.index]

    const dir = getDirection(gp, info)       // dir.dpad, dir.leftAnalog, dir.rightAnalog
    const btns = getButtonPress(gp, info)    // btns[0..16], null = unused
  }
  requestAnimationFrame(loop)
}
requestAnimationFrame(loop)
```

## Button index reference (W3C standard order)

Index 0–3: face buttons (a, b, x, y), 4–5: shoulders, 6–7: triggers, 8–9: back/start, 10–11: stick clicks, 12–15: D-pad, 16: guide.

Built-in friendly name profiles: **Sony** (vendor `054c`) and **Nintendo** (vendor `057e`, A/B swapped by default).
